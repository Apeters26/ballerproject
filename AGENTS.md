# Drone Lab: repository-first delivery

## User requirement

Apeters26/ballerproject is the durable source of truth for this project's website, specifications, roadmap, release plan, stories, acceptance criteria, evidence register, release notes, reusable project package, and product vision video. Do not require the user to save or re-upload assets generated by an agent.

## Before working

Read docs/project-package-requirements.md and docs/asset-recovery-status.md. Inspect the current branches and open pull requests. Preserve the original specification proposal in PR #1. Do not assume the deployed site is already backed up in this repository.

## Delivery rules

1. Save source, inputs, narration text, captions, and build instructions in Git before claiming a deliverable is preserved. Store generated media in Git when appropriate, or in explicitly versioned Git LFS/release assets with a durable reference and SHA-256 checksum committed here. Never commit secrets or credentials.
2. Push a review branch, read the remote tree back, and report the actual commit and pull request. A local file, temporary sandbox URL, hosted page, or object uploaded without a branch reference is not a completed repository backup.
3. A pull request being open is not a merge. A merge is not a deployment. Record each separately.
4. Publish only from a recorded source commit. Verify the actual published page and media after publication. Do not call the website updated based only on a local preview.
5. Treat implemented, verified, accepted, and shipped as separate evidence-backed states. Never infer simulator delivery from website/docs delivery. Do not invent test results, approval, story IDs, or release dates.
6. A narrated video must contain an actual audio stream, captions, a transcript, and synchronized chapter timings. Browser-only speech playback is not a substitute for an audio track in the MP4. Check decoded audio for non-silence, playback, seeking, and mobile behavior.
7. When an original artifact is inaccessible, mark it not recovered. Distinguish exact text recovered from conversation evidence from newly reconstructed code or media. Do not silently replace the original or call a reconstruction a recovery.
8. A reusable package must include its source and setup/build/test workflow. Do not claim it is installed in another agent until that installation is verified.

## Completion evidence

Every delivery summary should distinguish committed/pushed, merged, built/tested, accepted, and deployed. An unavailable original MP4 or site source remains a blocker, even when requirements and transcript have been recovered.
